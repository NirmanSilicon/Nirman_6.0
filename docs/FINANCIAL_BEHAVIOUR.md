# Statement behaviour and passport

Upload `mobile/demo/behaviour-test-statement.csv` with statement end **2026-06-30** to exercise the complete flow. It contains six complete calendar months, 43 rows, confirmed salary credits, tagged rent/utility/loan payments, and ordinary spending. The expected descriptive Financial Behaviour Index is **85.7/100**. The five contributions sum to the displayed index. This file is generated test data, not a real customer's statement.

The server calculates the index from the last 365 days of transactions. It requires at least three complete calendar months, confirmed income, and no more than 20% unclassified credits or debits. Otherwise it returns `insufficient_data` and no index. Transfers, refunds and loans are never automatically labelled income. The five factor weights are income consistency 20%, spending 20%, savings 20%, recurring obligations 15%, and cashflow stability 25%. The exact observed ratios, factor score and contribution are returned by the API and displayed in **Insights**. The rubric is in `src/uqual/behaviour.py` and is not trained or validated against repayment outcomes.

Coaching shows at most three factors scoring below 70, ordered weakest first. It gives budgeting suggestions, not promises to improve an official score or obtain credit. Loan-payment categories identify outflows, but the app does not know contractual due dates or whether payments were timely. Monthly categorized income, spending, obligations and surplus support the stability view. A what-if endpoint mechanically reduces classified optional debits by 0–30% and recalculates only the descriptive index; it does not predict future behaviour or alter the synthetic model score.

Narration rules suggest salary, transfers and refunds for confirmation. Specific debit labels such as rent, utilities, groceries and loan payments can be auto-applied with a visible rule/confidence indicator. Unknown transactions remain unknown. `/v1/statements/{id}/classifications` lists rows, flags near-duplicates and possible refunds, and `/v1/statements/{id}/category` records an owner correction with optimistic revision control. The original uploaded file is retained; a correction updates the normalized ledger and reruns scoring. This is a heuristic classifier, not a bank-verified category service. The synthetic model's SHAP features are shown separately as raw model associations, not additive points on the 0–100 index.

A signed-in owner may request `GET /v1/statements/{id}/behaviour`, including for records saved before this release. To prepare a passport, the owner enters an intended recipient and explicitly consents to `POST /v1/statements/{id}/passport-links`; this creates an audit-logged PDF link valid for 24 hours. The owner may list or revoke links. Category corrections revoke existing links for that statement. Revocation prevents further server downloads; it cannot recall copies already downloaded or forwarded. Anyone holding a live link can open it, so the intended-recipient label is not identity enforcement. No lender integration or automatic delivery exists yet. The recipient must verify the report and source independently. The PDF contains coverage, monthly evidence, the descriptive index and factor breakdown, and a clearly labelled synthetic demo index if one exists. It is not a bureau report or lending decision.

Run `source .venv/bin/activate && pytest -q tests/test_behaviour_passport.py` for upload, rubric, ownership and consent checks.
